# F02 validator evaluation — not for release

Base: c0f3b4f8bd03669b0eb2fdf82d02bea2387712f0. This isolated branch evaluates PyNaCl 1.6.2; no production imports, requirements, or release gates are changed. The three candidate wheel filenames and hashes were transcribed from https://pypi.org/project/PyNaCl/1.6.2/ (2026-11-24); PyPI reports publishing provenance for commit 4d5ea2812b2b86dce1a892d7dff5e3bd03c00f24. Metadata is not independently verified publisher attestation. Upstream reports the 2025-12-31 libsodium build addresses CVE-2025-69277; CVE-2025-15444 references the same underlying issue in bundled Perl distributions. See https://osv.dev/vulnerability/CVE-2025-15444 and https://doc.libsodium.org/advanced/point-arithmetic. Neither advisory scope nor patched binary identity is independently approved.

CI downloads hash-locked wheels, checks downloaded bytes separately, installs offline in dedicated jobs, and tests generated/RFC keys, malformed encodings, small-order and mixed-order points and seeded random classifications. No production keys, no custom cryptography. A passing evaluation does not itself resolve F02, establish an independent oracle, approve a new dependency or change OpenSSL policy. Independent artifact provenance, upstream patch verification, integration design and fail-closed regression tests remain required. The evaluation workflow/lock must not be merged into main as production requirements.
